# Сигнал для Android

Приложение рассчитано на Android 12–17 (API 31–37), архитектуры arm64-v8a, armeabi-v7a и x86_64. Интерфейс аккаунта, каналов и переписки собирается вместе с APK. Запросы аккаунта, история и медиа используют ваш сервер `https://13.143.172.92:9443`; без сервера общение недоступно. Голос, камера и демонстрация экрана работают через нативный LiveKit SDK, а не захват из WebView.

Доступны регистрация и вход по username, каналы аккаунта, приглашения по username с принятием или отказом, ссылки приглашения в канал, сообщения и управление каналом согласно роли. Голосовая комната рассчитана на 10 участников. В звонке есть микрофон, отключение входящего звука, камера и её переключение, выбор динамика или гарнитуры, полный экран камеры и трансляции. Нативная служба звонка позволяет возвращаться к переписке и сворачивать приложение; Android показывает уведомление активного звонка. Выход из аккаунта завершает его.

Показ экрана запрашивает системное подтверждение при каждом запуске. Поддерживаются исходные размеры захвата, 30/60 кадров/с, 12/24/40 Мбит/с и H.264/VP9/VP8. Можно передавать звук приложений вместе с микрофоном, если приложение-источник разрешает запись. Защищённые окна, DRM и приложения с запретом захвата могут показывать чёрный экран или не отдавать звук. Звук приложений смешивается с микрофоном: выключение микрофона прекращает его передачу.

Исходное разрешение — запрос захвата, а не обещание передачи без сжатия. WebRTC использует кодеки с потерями; фактические кадры, качество и задержка зависят от телефона, аппаратного кодека, нагрева, VPN и сети. Сервер SFU пересылает медиа без перекодирования. Для разгрузки телефона принимается одна выбранная демонстрация экрана. Принудительная остановка приложения или его выгрузка системой завершит звонок; Android не позволяет незаметно перезапустить демонстрацию без согласия пользователя.

## Сборка

Нужны Node.js 24, pnpm 11.25.0, JDK 21 и Android SDK. Gradle Wrapper 9.8.1 уже включён в исходники, Android Gradle Plugin закреплён на 9.4.1. Установите через SDK Manager `platform-tools`, `platforms;android-37.0` и `build-tools;37.0.0`. Укажите каталог SDK в `ANDROID_HOME` или локальном `android/local.properties` (`sdk.dir=...`). Локальный файл не добавляется в Git.

Из корня проекта в PowerShell:

```powershell
pnpm install --frozen-lockfile
pnpm build
./android/gradlew.bat -p android --no-daemon lintDebug assembleDebug
```

Для Linux/macOS последняя команда — `bash android/gradlew -p android --no-daemon lintDebug assembleDebug`. Gradle копирует готовый `dist/` в assets APK; при отсутствии собранного интерфейса сборка должна остановиться. После изменений интерфейса повторите `pnpm build` перед Android-сборкой.

Устанавливаемый файл: `android/app/build/outputs/apk/debug/app-debug.apk`. Debug-вариант имеет отдельный идентификатор `cloud.signal.android.debug` и может стоять рядом с обычным приложением. Подпись debug создаётся Android инструментами для разработки; APK разных CI-запусков может потребовать удаления предыдущего debug-варианта. Для постоянного использования и обновлений установите release с постоянной подписью.

## Подписанный выпуск и обновления

Храните постоянный ключ подписи и резервную копию вне репозитория. Все дальнейшие выпуски должны подписываться этим же ключом, иначе Android не примет обновление поверх установленного приложения. APK, пароли и файл ключа исключены из Git. Ключи не создаются заново при каждой сборке.

Задайте в текущем окружении четыре переменные, затем выполните сборку:

| Переменная | Значение |
| --- | --- |
| `SIGNAL_ANDROID_KEYSTORE` | Абсолютный путь к постоянному keystore вне исходников |
| `SIGNAL_ANDROID_KEYSTORE_PASSWORD` | Пароль keystore |
| `SIGNAL_ANDROID_KEY_ALIAS` | Alias ключа |
| `SIGNAL_ANDROID_KEY_PASSWORD` | Пароль ключа |

```powershell
pnpm build
./android/gradlew.bat -p android --no-daemon lintRelease assembleRelease
```

Без всех четырёх переменных сборка release завершается ошибкой. Файл: `android/app/build/outputs/apk/release/app-release.apk`. Проверьте его инструментом `apksigner verify --verbose` из SDK Build Tools 37.0.0, затем из корня выполните:

```powershell
node tools/prepare-android-release.mjs
```

Скрипт берёт версию из соседнего Gradle `output-metadata.json` и подготавливает `android/app/build/release/Signal-Android-<версия>.apk` и `latest.json` с размером и SHA-256. Параметр `--output <каталог>` позволяет выбрать другой каталог. Скрипт не подписывает APK и не публикует файлы на сервер.

Для следующего выпуска увеличьте `versionCode` и `versionName` в `android/app/build.gradle.kts`. На сервере разместите APK в `/downloads/android/`, а затем замените `/downloads/android/latest.json`, отдавая его без кэширования. Нативная кнопка обновления в настройках проверяет версию, загружает APK только с этого сервера, сверяет размер, SHA-256, package ID и ту же подпись. Установку подтверждает пользователь в системном установщике Android. До публикации манифеста и APK на сервере обновление из приложения недоступно.

## GitHub Actions

Workflow [Android APK](../.github/workflows/android.yml) запускается при изменениях Android или интерфейса и вручную на вкладке Actions. Он устанавливает зависимости по lockfile, собирает интерфейс, выполняет `lintDebug assembleDebug` и сохраняет устанавливаемый debug APK и отчёт lint в артефактах запуска на 14 дней. Для скачивания артефактов закрытого репозитория нужен доступ к нему.

Для подписанного выпуска добавьте в **Settings → Secrets and variables → Actions**:

| Secret | Значение |
| --- | --- |
| `SIGNAL_ANDROID_KEYSTORE_BASE64` | Base64 содержимое существующего постоянного файла keystore |
| `SIGNAL_ANDROID_KEYSTORE_PASSWORD` | Пароль keystore |
| `SIGNAL_ANDROID_KEY_ALIAS` | Alias ключа |
| `SIGNAL_ANDROID_KEY_PASSWORD` | Пароль ключа |

Затем выберите **Run workflow → signed_release**. Keystore восстанавливается только во временный каталог runner и удаляется после сборки. Workflow проверяет подпись и прикладывает release APK и `latest.json` к артефактам; публикация на сервер выполняется отдельно. CI не создаёт новый ключ подписи и не получает доступ к серверу.

## Проверка на телефонах

Сборка и статический анализ не подтверждают работу камеры и MediaProjection на физическом устройстве. Проверка на телефонах Android 12–17, включая одновременный VPN и звонок с 10 участниками, пока не проведена.

Перед распространением проверьте два телефона и настольный клиент из разных сетей: вход, принятие и отказ от приглашения, микрофон и Bluetooth, обе камеры и полный экран, 30/60 fps на движущемся экране, звук приложения, сворачивание и возврат в звонок, остановку из уведомления, отзыв разрешений, потерю интернета и обновление release поверх старого APK. На Android 13+ отдельно проверьте разрешение уведомлений, на Android 14+ — отмену и повторный запуск системного разрешения захвата. Сравните качество с VPN и без него; FPS и нагрузку следует измерять на передающем и принимающем устройстве.

Технические источники: [Android 17 SDK](https://developer.android.com/about/versions/17/setup-sdk), [подпись приложения](https://developer.android.com/studio/publish/app-signing), [MediaProjection](https://developer.android.com/media/grow/media-projection), [LiveKit Android](https://docs.livekit.io/transport/sdk-platforms/android/), [артефакты GitHub Actions](https://github.com/actions/upload-artifact).
